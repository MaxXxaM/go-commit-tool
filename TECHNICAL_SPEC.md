# Техническое задание: Go Multi-Module Development Utility

## Обзор проекта

Утилита командной строки для управления разработкой в мультимодульных Go проектах со сложными зависимостями. Позволяет переключаться между режимами локальной разработки (через go.work) и работой с удаленными версиями, автоматизирует версионирование и синхронизацию зависимостей.

## Основные возможности

### 1. Управление зависимостями

#### 1.1 Сканирование зависимостей
- Автоматическое обнаружение зависимостей через анализ `go.mod`
- Поддержка вложенных (транзитивных) зависимостей
- Построение дерева зависимостей проекта

#### 1.2 Типы размещения зависимостей
Утилита должна поддерживать два режима размещения локальных копий:

- **Локальные зависимости** - размещаются рядом с текущим проектом
  - Используются когда только один проект ссылается на зависимость
  - Пример структуры:
    ```
    /project-root/
      /my-service/
      /dependency-a/
      /dependency-b/
    ```

- **Глобальные зависимости (shared)** - размещаются в общей директории
  - Используются когда множество сервисов ссылается на зависимость
  - Пример структуры:
    ```
    /shared/
      /common-lib/
      /shared-utils/
    /projects/
      /service-1/
      /service-2/
    ```

- **Миграция между режимами** - возможность перевода зависимости из локального в глобальный режим и обратно в любой момент

### 2. Управление workspace (go.work)

#### 2.1 Динамическое формирование go.work
- Автоматическое создание/обновление `go.work` файла
- Включение только активных локальных зависимостей

#### 2.2 Режимы работы
- **go.work режим** - локальная разработка через workspace
- **go.mod режим** - прямой режим с использованием удаленных версий
- **Частичное переключение** - возможность работы с отдельными зависимостями локально, остальные через удаленные версии

#### 2.3 Custom replace директивы
- Поддержка пользовательских `replace` директив в go.mod
- Сохранение кастомных replace при переключении режимов

### 3. Версионирование и релизы

#### 3.1 Semantic Versioning
- Использование формата `v{major}.{minor}.{patch}` (например, v1.2.3)
- Автоматическое определение типа версии (major/minor/patch) на основе анализа изменений

#### 3.2 Анализ изменений для определения типа версии
Правила определения типа обновления версии:
- **Major** - breaking changes:
  - Удаление публичных функций/методов/типов
  - Изменение сигнатур публичных функций
  - Изменение поведения API несовместимым образом
- **Minor** - новая функциональность:
  - Добавление новых публичных функций/методов/типов
  - Новые возможности без breaking changes
- **Patch** - исправления:
  - Bugfix
  - Документация
  - Внутренние рефакторинги без изменения API

#### 3.3 Стратегия обновления зависимостей
- **Порядок обновления**: от листьев к корню дерева зависимостей
  1. Сначала обновляются модули, на которые никто не ссылается (листья)
  2. Затем их зависимые модули
  3. И так далее до корня дерева
- **Точечное обновление** - возможность фиксировать изменения только в выбранных модулях, не обновляя всё дерево

#### 3.4 Процесс релиза
Для каждого модуля в правильном порядке:
1. Коммит изменений (или использование существующего коммита)
2. Создание тега версии
3. Push в репозиторий
4. Обновление go.mod во всех зависимых модулях
5. Запуск `go mod tidy` для обновления go.sum

### 4. Миграция и клонирование репозиториев

#### 4.1 Namespace migration
Поддержка переноса модулей между репозиториями с сохранением истории:
- Перенос из `gitlab.com/parkky1/gateway` в `github.com/<new-namespace>/<new-name>`
- Клонирование всех веток
- Копирование всех тегов (версий)
- Обновление путей импорта в go.mod

#### 4.2 Операции клонирования
- Поддержка различных Git хостингов (GitHub, GitLab, Bitbucket, custom)
- Клонирование с сохранением всей истории
- Batch операции для множества модулей

### 5. Аутентификация и безопасность

#### 5.1 Поддержка методов аутентификации
- SSH ключи (по умолчанию из ~/.ssh)
- Personal Access Tokens (PAT)
- Git credentials helper
- Поддержка приватных репозиториев

#### 5.2 Конфигурация
- Хранение настроек аутентификации
- Per-repository credentials
- Глобальные и локальные настройки

### 6. Workflow и CLI команды

#### 6.1 Основной workflow
```
1. init       - Инициализация проекта, сканирование зависимостей
2. clone      - Клонирование зависимостей локально
3. local      - Переключение в режим локальной разработки (go.work)
4. [development work]
5. status     - Проверка состояния изменений
6. release    - Создание релизов с версионированием
7. remote     - Переключение обратно на удаленные версии
```

#### 6.2 Команды CLI

##### Инициализация и конфигурация
```bash
# Инициализация в текущей директории
go-mod-util init

# Сканирование и отображение дерева зависимостей
go-mod-util scan [--depth N]

# Управление конфигурацией
go-mod-util config set <key> <value>
go-mod-util config get <key>
```

##### Управление зависимостями
```bash
# Клонирование всех зависимостей
go-mod-util clone [--mode local|shared]

# Клонирование конкретной зависимости
go-mod-util clone <module-path> [--mode local|shared]

# Перевод зависимости между режимами
go-mod-util move <module-path> --to local|shared

# Удаление локальной копии
go-mod-util clean <module-path>
```

##### Переключение режимов
```bash
# Переключить всё на локальную разработку
go-mod-util switch local [--all]

# Переключить конкретные модули
go-mod-util switch local <module1> <module2>

# Переключить группу модулей по префиксу
go-mod-util switch local --prefix github.com/myorg

# Переключить обратно на удаленные версии
go-mod-util switch remote [--all]

# Показать текущий режим
go-mod-util status
```

##### Работа с версиями и релизами
```bash
# Показать изменения и предлагаемую версию
go-mod-util version check [module]

# Создать релиз (автоматическое определение версии)
go-mod-util release [module] [--auto]

# Создать релиз с указанием типа версии
go-mod-util release [module] --bump major|minor|patch

# Создать релиз с конкретной версией
go-mod-util release [module] --version v1.2.3

# Обновить зависимости после релиза
go-mod-util update-deps [--all]
```

##### Миграция репозиториев
```bash
# Перенос модуля в новый репозиторий
go-mod-util migrate <old-module-path> <new-module-path> \
  --update-imports \
  --push

# Обновление импортов во всех зависимых модулях
go-mod-util update-imports <old-path> <new-path>
```

##### Информация и статус
```bash
# Показать дерево зависимостей
go-mod-util tree [--local-only]

# Показать статус всех модулей
go-mod-util status [--verbose]

# Показать измененные модули
go-mod-util diff

# Проверка консистентности версий
go-mod-util verify
```

##### Custom replace директивы
```bash
# Добавить custom replace
go-mod-util replace add <module> <replacement>

# Удалить custom replace
go-mod-util replace remove <module>

# Показать все replace директивы
go-mod-util replace list
```

### 7. Структура конфигурации

#### 7.1 Конфигурационный файл (.gomodutil.yaml)
```yaml
# Корневая директория для shared зависимостей
shared_dir: "../shared"

# Стратегия размещения по умолчанию
default_placement: "auto"  # auto, local, shared

# Правила для автоматического определения placement
placement_rules:
  - pattern: "github.com/myorg/common-*"
    mode: "shared"
  - pattern: "github.com/myorg/service-*"
    mode: "local"

# Аутентификация
auth:
  github.com:
    method: "token"
    token_env: "GITHUB_TOKEN"
  gitlab.com:
    method: "ssh"

# Настройки версионирования
versioning:
  # Автоматическое определение типа версии
  auto_detect: true
  # Правила для определения типа изменений
  change_detection:
    breaking_changes:
      - "removed public function"
      - "changed function signature"
    features:
      - "added public function"
      - "new API endpoint"

# Настройки релиза
release:
  # Автоматический push после тегирования
  auto_push: true
  # Создание changelog
  create_changelog: false
  # Запуск тестов перед релизом
  run_tests: true

# Исключения (модули, которые не нужно обрабатывать)
exclude:
  - "golang.org/x/*"
  - "github.com/external/*"
```

#### 7.2 Метаданные проекта (.gomodutil/metadata.json)
```json
{
  "modules": {
    "github.com/myorg/module-a": {
      "placement": "local",
      "path": "../module-a",
      "mode": "workspace",
      "current_version": "v1.2.3",
      "has_changes": true
    },
    "github.com/myorg/common-lib": {
      "placement": "shared",
      "path": "../../shared/common-lib",
      "mode": "remote",
      "current_version": "v2.0.1",
      "has_changes": false
    }
  },
  "custom_replaces": [
    {
      "module": "example.com/old",
      "replacement": "example.com/new"
    }
  ],
  "dependency_tree": {
    // Кэш дерева зависимостей
  }
}
```

## Технические требования

### 8. Реализация

#### 8.1 Язык и технологии
- **Язык**: Go 1.21+
- **CLI framework**: cobra + viper (или аналоги)
- **Git operations**: go-git или git CLI wrapper
- **Config**: YAML/JSON parsing

#### 8.2 Архитектура
```
/cmd
  /gomodutil      - Entry point
/internal
  /analyzer       - Анализ go.mod и построение дерева зависимостей
  /cloner         - Клонирование и управление репозиториями
  /workspace      - Управление go.work
  /versioning     - Определение версий и создание релизов
  /migrate        - Миграция репозиториев
  /config         - Управление конфигурацией
  /git            - Git операции
/pkg
  /types          - Общие типы данных
  /utils          - Утилиты
```

#### 8.3 Основные компоненты

##### DependencyAnalyzer
- Парсинг go.mod файлов
- Построение графа зависимостей
- Определение порядка обновления (topological sort)

##### ModuleCloner
- Клонирование репозиториев
- Управление размещением (local/shared)
- Миграция между режимами

##### WorkspaceManager
- Создание/обновление go.work
- Переключение между режимами (workspace/remote)
- Управление replace директивами

##### VersionAnalyzer
- Анализ git diff для определения типа изменений
- Определение типа версии (major/minor/patch)
- Создание тегов

##### ReleaseManager
- Оркестрация процесса релиза
- Обновление зависимостей в правильном порядке
- Коммиты и push изменений

##### RepositoryMigrator
- Клонирование с историей
- Обновление namespace в go.mod
- Обновление импортов в зависимых модулях

### 9. Нефункциональные требования

#### 9.1 Производительность
- Параллельное клонирование репозиториев (когда возможно)
- Кэширование результатов анализа
- Инкрементальные операции

#### 9.2 Надежность
- Проверка состояния перед опасными операциями
- Возможность отката изменений (dry-run режим)
- Валидация конфигурации
- Проверка на конфликты версий

#### 9.3 Usability
- Понятные сообщения об ошибках
- Интерактивные подсказки
- Прогресс-бары для длительных операций
- Цветной вывод в терминал

#### 9.4 Безопасность
- Безопасное хранение credentials
- Проверка SSH ключей
- Валидация URL репозиториев

## Будущие возможности (вне текущего scope)

1. **Автоматическое создание Pull Requests**
   - Интеграция с GitHub/GitLab API

2. **CI/CD интеграция**
   - GitHub Actions / GitLab CI плагины
   - Автоматическая проверка совместимости версий

3. **Web UI**
   - Визуализация дерева зависимостей
   - Управление через браузер

4. **Уведомления**
   - Slack/Discord интеграция
   - Email уведомления о релизах

5. **Расширенная аналитика**
   - История изменений версий
   - Статистика по зависимостям
   - Анализ security vulnerabilities

## Глоссарий

- **Module** - Go модуль (директория с go.mod)
- **Workspace** - Go workspace (go.work файл)
- **Local placement** - размещение зависимости рядом с текущим проектом
- **Shared placement** - размещение зависимости в общей директории
- **Dependency tree** - граф зависимостей модулей
- **Release** - создание версии (тега) и обновление зависимостей
- **Migration** - перенос модуля между репозиториями
